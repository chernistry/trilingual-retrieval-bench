# Andantino: synthetic corpus and retrieval quality gate

A synthetic document corpus in Russian, English and Hebrew, with gold queries and
check scripts. The documents are invented (leases, payslips, medical letters, bills,
contracts and similar); they are meant to contain no real people or identifiers. It is
used to gate retrieval quality of a local document search engine and to demo search
without exposing anyone's files.

The documents and the gold queries are machine-generated from the
prompts in `tools/corpus-tasks.jsonl` and checked by `tools/check_corpus.py`. No retrieval
results are recorded in this repository yet.

## Layout

| Path | Contents |
|---|---|
| `corpus/{ru,en,he}/` | Markdown documents, one language per folder, named `bNN-<slug>.md` where `bNN` is the batch (`b01`..`b10`) |
| `gold/bNN.jsonl` | Gold queries for batch `bNN` |
| `gold/bNN.files` | Manifest of the batch: one corpus path per line |
| `gold/all.jsonl` | Merged gold set with absolute paths; generated by `make eval`, not tracked |
| `tools/check_corpus.py` | Batch acceptance check |
| `tools/merge_gold.py` | Merges `gold/b*.jsonl` into one set |
| `tools/corpus-tasks.jsonl` | Generation prompts used to produce each batch |
| `scrubber/` | `scrub.py`, a pseudonymisation script for text files, with its tests and README |
| `demo/` | Script for recording a terminal demo (`demo.tape`) and its helper `q` |

## Gold file format

`gold/bNN.jsonl` holds one JSON object per line:

```json
{"q": "query text", "lang": "ru", "expect": ["corpus/ru/b01-<slug>.md"], "kind": "date"}
```

- `q`: the query as a user would type it.
- `lang`: query language, `ru`, `en` or `he`.
- `expect`: corpus paths, relative to the repository root, of the documents that answer it.
  The document language may differ from `lang` (cross-lingual query).
- `kind`: `fact`, `date`, `amount` or `howto`.

`tools/merge_gold.py` adds `id`, `slice` (the query language, or `xling` when it differs
from the document language) and `relevant`, and turns `expect` into absolute paths.

## Checking the corpus

`tools/check_corpus.py` needs only Python 3 and the standard library:

```
python3 tools/check_corpus.py b01
make check            # all batches
```

For one batch it checks that the manifest and gold rows point at existing files, each
document starts with a heading and has 120 to 1200 words, its language matches its folder,
and it has no 9-digit numbers, Israeli mobile-number shapes or real-provider e-mail
addresses. It exits 0 when the batch is accepted.

## Indexing and evaluation (external engine)

`make index` and `make eval` need a separate local search engine that provides
`kb_index.py` and `kb_eval.py`. It is not part of this repository. Point `KB` at its
directory, and optionally `PY` at the Python interpreter that runs it (default `python3`):

```
make index KB=/path/to/engine
make eval  KB=/path/to/engine PY=/path/to/python
```

`KB` can also be set in the environment. `make index` builds the corpus into a separate
table (`chunks_synth`, via `KB_TABLE`), so an existing table is not touched. `make eval`
writes its result to `out/`. `demo/q` also reads `KB`; it needs zsh and a local search command named `kb`, and is not required for the checks.

## Preparing your own documents

`scrubber/scrub.py` is a single-file Python 3.10+ script that uses only the standard
library. It replaces identifying tokens in prose files with stable pseudonyms such as
`<HOST_2>` or `<EMAIL_1>`, and writes each result under a neutral alias path
(`scrubbed/<16 hex>/<name>`) instead of the original path. It reads `.md`, `.markdown`,
`.txt`, `.rst`, `.org` and `.adoc` files and does not open a network connection.

```
python3 scrubber/scrub.py harvest --root NOTES_DIR --out denylist.json
python3 scrubber/scrub.py scrub   --root NOTES_DIR --out OUT_DIR --denylist denylist.json
python3 scrubber/scrub.py verify  --scrubbed OUT_DIR --denylist denylist.json
```

- `harvest` builds a denylist from the source tree: e-mail addresses, domains and host
  names, ticket prefixes, IPv4 addresses, `@handles`, git remotes and authors, package
  manifest names, company names with a legal suffix, and frequent capitalised words.
- `scrub` replaces the denylist terms in each document. A document whose output still
  contains a denylist term is refused and not written.
- `verify` re-scans the output for denylist terms that survived.
- `reverse` maps an alias back to its source path through a local mapping file.

The salt and the mapping file are kept in `~/.config/text-scrubber/` (or in the directory
named by `SCRUBBER_DIR`), outside the output. The denylist file lists the identifiers in
clear. Keep both away from anything you publish. See `scrubber/README.md` for all options
and the known limits.

The script lowers the chance that identifiers leak; it does not guarantee that they do not.
It replaces only what its rules and the denylist name. Its rules and word lists are tuned
for English, and its patterns match Latin letters only, so capitalised words written in
Cyrillic or Hebrew script are not harvested; Latin-script identifiers such as e-mail
addresses and domains are.
It does not look for credentials or for personal data in free text. Read the denylist and
the output before sharing either.

The scrubber's tests need `pytest`; the corpus checks need only the standard library. Run
both with `make test`.
